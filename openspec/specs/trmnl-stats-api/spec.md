## Requirements
### Requirement: TRMNL access token
The system SHALL provide a TRMNL-specific access token that grants read-only access to the public TRMNL polling endpoints, decoupled from the user login session.

#### Scenario: Token required for polling endpoints
- **WHEN** a request is made to a TRMNL polling endpoint without a valid `token` query parameter
- **THEN** the endpoint SHALL return `401 Unauthorized`
- **AND** no stat data SHALL be returned

#### Scenario: Valid token grants access
- **WHEN** a request includes the configured TRMNL access token as the `token` query parameter
- **THEN** the endpoint SHALL return the requested stat data as JSON

#### Scenario: Token generation
- **WHEN** the system is first set up or the token is regenerated by an admin
- **THEN** a new random token SHALL be generated and persisted
- **AND** the previous token SHALL stop being accepted

### Requirement: Character stats polling endpoint
The system SHALL expose a public read-only JSON endpoint returning a character's ability scores, HP/AC, level, XP, and derived modifiers for TRMNL polling.

#### Scenario: Request character stats
- **WHEN** a client polls `/api/trmnl/character-stats` with a valid token and a `character_id`
- **THEN** the response SHALL include `name`, `race`, `class`, `level`, `xp`, `hp_current`, `hp_max`, `ac`, `initiative`, and the six ability scores (`str`, `dex`, `con`, `int`, `wis`, `cha`) with their modifiers
- **AND** the response SHALL be valid JSON suitable for Liquid templating

#### Scenario: Unknown character
- **WHEN** a client polls with a valid token but a `character_id` that does not exist
- **THEN** the endpoint SHALL return `404 Not Found`

### Requirement: Campaign progress stats polling endpoint
The system SHALL expose a public read-only JSON endpoint returning campaign progress stats for a character, derived from the existing `GetCharacterStats` data.

#### Scenario: Request campaign stats
- **WHEN** a client polls `/api/trmnl/campaign-stats` with a valid token and a `character_id`
- **THEN** the response SHALL include session count, total XP earned, total gold earned, quest breakdown, rest breakdown, top NPCs, and dice roll summary
- **AND** the response SHALL be valid JSON suitable for Liquid templating

#### Scenario: Unknown character
- **WHEN** a client polls with a valid token but a `character_id` that does not exist
- **THEN** the endpoint SHALL return `404 Not Found`

### Requirement: Read-only and stateless
TRMNL polling endpoints SHALL be strictly read-only and SHALL NOT mutate campaign, character, or session data.

#### Scenario: No state mutation
- **WHEN** a client polls either TRMNL endpoint
- **THEN** no records SHALL be created, updated, or deleted
- **AND** the endpoint SHALL only support `GET`
